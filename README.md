## 项目概述

本项目使用 Sing-box 与 Clash/Mihomo 构建一个透明代理网关（TProxy），可拦截局域网内的 TCP/UDP 流量并根据 DNS/策略进行分流与出站代理转发。

## 重要提示

• 请务必修改并使用可信的 DNS（建议使用 DoT/DoH）。使用默认或不可信的 DNS 可能导致 DNS 污染或投毒。

## 配置文件说明

### config.json（Sing-box）

主要配置项：

- 监听地址：`::`（IPv6/双栈）
- 监听端口：`12345`（TProxy 端口）
- DNS（国内）：`223.5.5.5:443`（阿里云 DoH）
- DNS（国外）：`1.1.1.1:443`（Cloudflare DoH，通常需要走代理）
- 出站：示例使用 Hysteria2 连接到 `${hysteria2.yourserver.com}:443`

需要修改的出站示例：

```json
{
  "outbounds": [
    {
      "server": "你的服务器地址",
      "server_port": 443,
      "password": "你的密码"
    }
  ]
}
```

### clash.yaml（Clash / Mihomo DNS）

主要配置项：

- DNS 监听：`:53`（在本机 53 端口监听）
- 主 DNS：`223.5.5.5`（阿里云）
- 备用 DNS：`1.1.1.1`（国外，通常走代理）
- GeoIP 策略：启用 CN，以便国内 IP 优先使用主 DNS

## 快速开始

下面给出最小可运行流程，适用于已有 sing-box 与 mihomo 二进制的机器。

### 1. 校验并启动 Sing-box

下载（示例）：

https://github.com/SagerNet/sing-box/releases

检查版本：

```bash
./sing-box version
```

启动（如需后台管理，请使用 systemd）：

```bash
./sing-box run -c config.json
```

（可选）systemd 简易示例服务：

```ini
[Unit]
Description=sing-box
After=network.target

[Service]
Type=simple
User=root
ExecStart=/opt/sing-box/sing-box run -c /opt/sing-box/config.json
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

### 2. 配置并应用 iptables/路由 规则

在执行规则脚本前，请先修改脚本顶部的参数：

- 内网网段（示例）：`10.0.1.0/24`
- Sing-box 机器内网 IP（示例）：`10.0.1.114`
- TProxy 端口（与 `config.json` 保持一致）：`12345`
- SSH 服务器 IP：将其排除以免被拦截

示例修改后执行脚本：

```bash
bash iptables_rules.sh
```

规则说明：

- 路由表设置：将被标记（mark=1）的流量路由到本机回环或指定路由表
- 局域网流量：将来自其他机器的符合条件流量重定向到 TProxy
- 本机流量：将本机发出的需要代理的流量拦截到 TProxy
- 特殊处理：排除私有地址段、SSH、和局域网管理地址

### 3. 启动 Clash / Mihomo

```bash
./mihomo-linux-amd64 -f clash.yaml
```

（二进制名称视发行版而定）

### 4. 本机 DNS 设置

将本机 DNS 指向本地 Clash：

编辑 `/etc/resolv.conf`，将 `nameserver` 指向 `127.0.0.1`：

```bash
sudo tee /etc/resolv.conf <<'EOF'
# Generated by user
nameserver 127.0.0.1
EOF
```

注意：某些系统（如 systemd-resolved、NetworkManager）会覆盖 `resolv.conf`，请根据系统配置持久化本地 DNS。

### 5. 测试连接

```bash
# 测试国内站点
curl -I https://www.baidu.com

# 测试国外站点
curl -I https://www.google.com

# 验证 DNS 解析
nslookup www.google.com 127.0.0.1
```

## 架构流程

局域网其他机器 -> （DNS:53 / 流量） -> Sing-box 网关（Clash DNS + Sing-box TProxy）-> 出站代理（Hysteria2 等）-> 互联网

简化示意：

```
局域网机器  ──>  Sing-box 网关 [Clash DNS (53) + Sing-box TProxy (12345)]  ──>  出站代理 (Hysteria2)  ──>  互联网
```

## 常见参数修改

- 修改 TProxy 端口：同时更新 `config.json` 与 `iptables_rules.sh`
- 修改内网网段：在 `iptables_rules.sh` 中替换 `10.0.1.0/24`
- 修改 Sing-box IP：在 `iptables_rules.sh` 中替换为实际 IP
- 修改出站代理：在 `config.json` 的 `outbounds` 中调整
- 修改 DNS 策略：更新 `clash.yaml` 中的 `nameserver`/`fallback`

## 故障排查

### DNS 投毒 / 解析异常

症状：国外域名解析出国内地址或解析不正确。

解决步骤：
1. 检查 `/etc/resolv.conf` 是否指向 `127.0.0.1`，确认系统没有使用不可信 DNS。
2. 确认 Clash 已启动并监听本地 53 端口。
3. 重启 Clash 与 Sing-box：`systemctl restart mihomo` / `systemctl restart sing-box`（如有 systemd 单元）。

### SSH 被代理导致连接中断

症状：通过网关连接的 SSH 会话被中断或不可用。

解决步骤：
1. 在 `iptables_rules.sh` 中将 SSH 服务器 IP 排除（RETURN 或不打标记）。
2. 确认规则存在：`iptables -t mangle -L -n`。
3. 重新应用规则：`bash iptables_rules.sh`。

### 局域网其他机器无法上网

症状：通过网关的机器无法访问外网。

解决步骤：
1. 检查 iptables/路由是否已正确应用并生效。
2. 检查网关的 IP、内网网段设置是否匹配实际网络。
3. 确认 Sing-box 与 Clash 是否在运行，并检查日志。
4. 查看系统日志（示例）：`journalctl -u sing-box -f` 或 `tail -f /var/log/syslog`。
5. 确认内核转发：`sysctl net.ipv4.ip_forward`，应为 `1`。
